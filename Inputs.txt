“10. Employee Leave – Leave Request”

FEATURE SET IV:
1. Employee Details
2. Department
3. Leave Request
4. Leave Dates
5. Leave History
6. Approval Status

Create the algorithm using standard algorithm-writing rules. Do NOT create a flowchart or diagram. Write ONLY the numbered algorithm steps.

ALGORITHM:

1. Start.
2. Enter Employee ID, Employee Name, Email, and Contact Number.
3. Verify whether the Employee Details are valid.
4. If the Employee Details are invalid, display “Invalid Employee Details” and enter the details again.
5. If valid, identify/select the Employee Department.
6. Enter the Leave Request details, including Leave Reason.
7. Enter the Leave Start Date and Leave End Date.
8. Validate the Leave Dates.
9. If the Leave Dates are invalid, display “Invalid Leave Dates” and enter the dates again.
10. Check the Employee’s Leave History for previous leave requests.
11. Review the current Leave Request with the Leave History.
12. Validate the complete Leave Request.
13. If the Leave Request is invalid, display “Invalid Leave Request” and enter the request details again.
14. If valid, submit the Leave Request.
15. Set the Approval Status as “Pending”.
16. Send the Leave Request to the concerned Manager/Authority for approval.
17. Check the Approval Status.
18. If the request is Approved, display “Leave Request Approved”.
19. If the request is Rejected, display “Leave Request Rejected”.
20. If the request is Pending, display “Leave Request Pending”.
21. Update the Leave History with the Leave Request and its Approval Status.
22. Display the Final Leave Request Status.
23. End.

- Start with “Start” and finish with “End”.
- Number every step in sequential order.
- Keep each step clear, simple, and unambiguous.
- Include all Feature Set IV items:
  Employee Details, Department, Leave Request, Leave Dates, Leave History, and Approval Status.
- Use input steps for entering employee and leave information.
- Use process steps for validation, submission, status setting, and history updating.
- Use decision conditions for validation and approval status.
- Clearly handle YES/NO conditions.
- Invalid employee details must return to employee-details entry.
- Invalid leave dates must return to leave-date entry.
- Invalid leave requests must return to leave-request entry.
- Only a valid leave request should be submitted.
- Set Approval Status to “Pending” after submission.
- Handle all three approval outcomes: Approved, Rejected, and Pending.
- Update Leave History after processing the request.
- Display the final approval status before ending.
- Do not skip any step.
- Do not add unrelated features.
- Make the algorithm suitable for a BCA/college project and software/database documentation.
